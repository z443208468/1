# 苍岐美术生产规则

**适用任务**　依演出已登记的工单和用户授权，制作实体设计或完整 PNG。AI 负责生产、技术检查、登记和场次打包。用户在角色定版和整场交接时验收图像。资产系统中的“可复用”“已登记”和版本已采纳，是生产记录；用户结论另按具体版本记录。

**成品应呈现什么**　同一角色切换视线或表情时，玩家能认出神情变化，身体、衣服和头的位置保持稳定。切到近景或 CG，脸、年龄与衣装仍能和该场的角色设计对上。背景给人物留得下站位，场内物件只出现在此刻应在的位置。游戏内切换、缩放、遮挡和存读档另按实机结果记录。

## A0　接单与分工

工单字段和需演出定案的事项见[演出册](苍岐演出与美术统一规则.md)。命令、参数、目录、工具限制和交接包生成方法见[《工具用法》](../config/工具用法.md)。先按工单类型选路线。

| 工单 | 执行顺序 | 可交付的证据 |
|---|---|---|
| 实体设计或设计修订 | A1 → A2，缺设计图时按 A3 生成 | 设计图和实体版本已登记，设计单可复用，下游绑定可回读 |
| 有场所空间的背景、CG | A1 → A4 的 S0–S6 → 技术检查与登记 → S7 整场验收 | 成图版本、同机位结构依据、逐实体叠图及跨状态对照 |
| 其他背景／CG、对象层已开放的独立道具 | A1 → A3 → A4 → A7 | 采纳版本、工单附件及用户对照图 |
| 人物全身或近景基准 | A1 → A5 定姿势及构图 → A3 → A5 定尺寸 → A7 | 基准版本、原图边缘和定尺寸结果。首张样板进入角色定版 |
| 表情或视线差分 | A1 → A6 编辑并贴回 → A7 | 当前状态成品与技术结果、逐眼图、三格对照和兼容组切换预览 |
| 来源采纳后复制同图 | 共同五第 6 点 | 来源与本场采纳版本的 SHA-256 一致 |

人物线与非人物线各由一个 Codex 主会话调度，可以并行。每线最多三个生产者，有可做工单时保持三个，完成即补位。主会话派工、核对记录与回读，生产者出图。
- **人物按套派。** 同人物、年龄、服装、姿势的一套交同一生产者；身份和衣装设计交第一套的生产者，CG 专用人物交人物线空闲生产者。只在[A5 角色定版](#art-early)所述范围等待用户。
- **非人物按单派。** 总体设计先登记，再派组成部分。场所清单和白模各版本由非人物线指定一名生产者维护，各机位可共用。跨线先回读谁已领取，避免重复。
- **生产记录。** 提示词、附图、输出、技术结果和人工操作引用工具原生记录。主会话核字段、依赖、技术证据及交接资料是否齐全。生产者按[共同四](#art-common-4)作一次快速目视检查，结论与警告写进本单。视觉质量由用户判定。

## A1　开工核对

<a id="art-common-1"></a>

### 共同一　读工单，确认能开工

主会话核对授权、字段、绑定与当前依赖后直接派工。生产者接单发现差异，交主会话处理；其余可做工单继续。开工不增加逐单用户审核。

1. **读取工单和资源。** 读 `brief.md`、`description`、`technical`、`entities`、绑定版本与附件、`depends_on`。从资源库另读 `production.purpose`，人物另读 `portraitRole`。景别取 `technical.frame`，基准关系取工单依赖。画风见 A3，工单上下文里的旧画风信息及 `art_request` 不作画面依据。
2. **本批范围与依赖。** 只做用户授权的单。已授权前置未完成，同线先派前置。跨线先核是否已有人领取，未派就安排对应生产线领取，已在做的回读进度。依赖成环按演出册 5f 修正。前置未获本次授权，依赖它的单只列最终报告，不计失败。前置基准或设计需要重做时，等新版登记或采纳后再制作下游。
3. **开工条件。** 每单有正文及已登记目标实体。成图单有用途、目标宽高，人物另有景别、兼容组和分类。设计前置须为“可复用”，所用成图前置须已登记并采纳。用于制作的设计版本应有可取回的设计图；“待用户审”与“用户已审”均可使用，已被用户退回、已暂停或失效的版本不得作为新前置。角色定版对后续派工的限制见 A5。新设计单只核目标实体，修订单另核原版本。发现多目标设计单按演出册[拆分已审设计单](苍岐演出与美术统一规则.md#split-design-job)处理。
4. **核对和修复绑定。** 对照 4b／4d／4e、工单正文和绑定版本核实际承载。漏绑已有适用版本由主会话补绑；已有先行设计单且版本为空则排队。能由已审决定唯一辨认的误绑按演出册[误绑处理](苍岐演出与美术统一规则.md#prune-render-entities)修本单并回读。涉及场所固定实体时须连同 A4 的机位可见性证据核对。范围不明、相互矛盾、缺决策或缺实体时，主会话按演出册[问题退回](苍岐演出与美术统一规则.md#handoff-return)追到回读。找不到用户结论的既有版本按 A2 第 4 点处理。只暂停该单及受影响下游。
5. **依据。** 工单正文和绑定版本落实已审演出。资源说明与正文的小差异在单内注明；主体、朝向、空间位置或是否入画相互冲突时，按上点退回定案。
6. **整图交付边界。** 完整画面工单附加的 PSD／CSP 分层、组件和像素级构图要求记入忽略项，其余照做。人物旧交付模式修正为 `whole-image`，保留其他字段与历史引用。画布、定尺寸锚点和技术检查框仍按规格验。用途本身是独立叠加素材或超出当前引擎能力的单，走演出册“问题退回”。已定稿底图的局部修订、同规格表情差分按 A3／A6 执行。
7. **用户验收清单。** 只列工单写明且画面可见的要求。人物逐个节拍列全，包括衣料光泽、年龄、姿态、持物及状态。非人物只列点名主体和主要位置关系。由立绘持有的物件在背景留位。

**旧设计与候选。** 先确认授权、现行需求与依赖，失效需求先交演出修正。旧候选只替代生图，基准仍查原图边缘，差分从贴回基准起。旧文件留原处，后续产物进本单新目录。旧包、旧图和 `work/art-workflows` 只读。旧包仅供身份、外观、设计及 A3 指定画风参考，忽略其中的 Assetelier、`postprocess`、`layer_contract`、`qa_report_path`、`raw_capture` 生产指令。仅已核验并登记的旧资产可正式复用。

## A2　实体设计与版本

<a id="art-common-2"></a>

### 共同二　设计稿

1. **沿用或修订。** 成图可使用绑定的适用版本。修订单按原版本和已定差异出新图，保留旧版记录。
2. **查重。** 沿用 A1 查询，再查旧包。已有适用且未被退回的正式设计，复用该版本并按第 5 点改绑；不得为缺用户结论重复生图。
3. **设计产物。** 一单一主体。缺适用设计时按 A3 生成不透明设计图，附风格图和相关既有设计。默认 2048×2048，以工单指定尺寸为先。交原图，不走成图定尺寸。非关键留白可标“改编补充”，身份、衣装、年龄、主体结构和布局未定时退演出。场所总体设计还须有可读的俯视平面，供 A4 的 S0 使用。
4. **版本的用户状态。** 技术检查通过即登记，设计说明首行写“待用户审”。用户通过该具体版本后，在其 `notes` 首行写“用户已审”，保留原备注，引用实际决定。回读以该版本最新有效用户记录为准。历史版本须有对应版本的用户通过证据才能沿用结论；仅有旧式审图标记、缺结论或只见候选文件时，不推定用户已审。旧标记及原备注保留为历史；使用未取得用户确认的已登记旧图时，补齐适用的技术证据并记录本次待用户审状态。若已有明确退回记录，转 A7 返工。
5. **登记与改绑。** 技术检查与生产者一瞥均通过后，登记带图路径的实体版本，实体版本及设计工单置“可复用”。将仍直接等待该设计单的下游改绑到实际采用版。已登记成品保留当时依据；用户退回后的影响范围、返工和版本替换按 A7。

用户在 A5 定版或整场交接时，对照原文、工单和已有设计判定以下各项。

| 设计对象 | 图上应能读到的内容 | 用户审核重点 |
|---|---|---|
| 人物身份 | 脸型、五官、发型发色、体型、年龄和身份特征。有年龄变化时记适用阶段 | 工单逐项完整、与已有设计连续、无未经决定的增删 |
| 服饰（独立实体与版本） | 款式、层次、材质、颜色、配饰和必要方向视图，记录与人物的对应关系 | 同上，另核说明和实体记录中的衣装关系 |
| 场所、建筑、物件 | 全体结构、轮廓、各部分位置、比例、材质与颜色，含镜头未露出的部分。独立子实体仅在总体图画位置和轮廓，另单设计 | 另核场所俯视平面的位置、朝向、大致尺寸；按 A4 非人物退回项，兼查点名主体是否齐全 |

## A3　出图、参考与文件

<a id="art-common-3"></a>

### 共同三　用 Forge 生图

1. **生成要求。** 每次整图生成使用 UTF-8 提示词，写全本单可见要求、项目风格锚、工单尺寸与透明性、构图和逐张参考图的作用。空间关系用方位或大致占比表达。固定提示词及写法查《工具用法》。

   **CQ_STYLE_REF_01。** 使用 `D:/CangqiStudio/Cangqi-ArtLab/outputs/v3_1/asset-manifest.json` 顶层 `style_anchor` 的原文，略去最后一句指向旧 JPG 的附图要求。风格图取同项目 `production/Cangqi_Act01_ArtPlan_v3_1_JP/references/`。只参考线条、边缘、上色、材质和细节组织。局部重绘、整体统一与表情差分不附风格图、不写风格锚。

   | 画面类别 | 风格图 | SHA256 |
   |---|---|---|
   | 人物全身或近景基准 | `style_reference_character.png` | `BBCD06DB134FFBD63C501729A8A6968B9DAD4D2AED3FE62C8FA3C597E2EF5C62` |
   | 背景、CG、道具及所有设计图 | `style_reference_scene.png` | `BA2169DBD9F0CC566539C2BCC3DE8B120E45C1A400A22D646C516036485BCF9C` |

2. **实际附图。** 场所背景／CG 按 A4 的 S6 分配五张参考。其他整图依次附设计图、采纳基准、白模、风格图；每次最多五张。超限优先保留风格图、身份或主体设计、已采纳基准、其他依赖成图、白模、衣装设计。CG 必须能辨识每一位人物的身份设计，文字可补其他可省参考。必要资料无法在额度内清楚表达时，退演出调整构图或拆镜，其他可做单继续。
3. **工具与产物。** 整图使用项目既有 Forge 路由，人物白模用 PosePipeline，场所白模按 A4。局部修补和明确指定的本地保底用 ComfyUI，差分按 A6。只用《工具用法》列明的工具与路由，不调用宿主生图（第 6 点备选除外）、不自编脚本、不改 Forge 上游。每单工作目录为 `D:/CangqiStudio/data/projects/<项目ID>/forge/<工单ID>/`。各轮新编号，不覆盖。提示词与工具输入、原图、白模、来源采纳图、成品及审核图分别保留。基准成品在 `final-NN/frames/`，背景／CG／道具成品为 `final-NN/background.png`，差分成品为 `final-NN` 中的整图。检查图只用于审核。
4. **透明素材。** 核原图预览中的透明通道和主体四周。模型无原生透明时直接用纯绿底生成，去背后以同轮 `keyed.png` 作原图。其余假透明先整张重出一次，仍假透明则走纯绿底。绿幕底色不纯时重出，不手工抠图。计数见 A7。
5. **定稿图局部修改。** 背景、CG、设计图的局部修订依工单或用户退回说明保留其余部分。修补／替换用局部重绘，多处依次修改；去字恢复原处背景，加物件先生成透明物件再贴合。透明人物基准和道具的局部问题整张重出。保留改后完整图、底图和中间产物，按实际修改范围做共同四的局部检查。差分用 A6 的头部框。

   **整体统一。** 工单或用户意见要求改善局部修补的接缝时，取本轮通过技术检查的修补图，按工具手册固定句让 Forge 原样重画一次。统一图按整图查技术，局部范围检查仅用于修补图。保留两版，按本单类型将通过技术检查及一瞥的统一图登记为候审成品，附修补图供用户并排选取。用户选择修补图时按 A7 登记、采纳所选文件并回填对应工单。统一图被拦截或技术失败，候审成品用已通过技术检查的修补图。接缝、物件增减和两版优劣留用户确认，已采纳图不为此重画。
6. **取回与重试。** 已有运行标识或作业记录显示已提交待取回，先取回原作业。没有可取回作业的服务错误保留原轮次，按 A7 计数，重试用新编号。
   - 同一工单的整图经 Forge 本机 Codex 路由连续三次超时，且三次都无可取回的运行标识，下一轮用宿主生图一次。执行该单的生产者沿用现行提示词与参考图，按《工具用法》保存输出和调用记录。其他情形不用宿主生图。
   - 宿主调用自开始起 400 秒仍无图，停止该轮，按服务未出图计一次技术失败。出图则照常计数，回到 A0 的原工序。备选仍失败，按 A7 记录反复技术失败及已有证据，继续其他可做项。
   - 该轮产物用于候审成图时，在版本 `note` 写“<工单ID> 宿主生图（Forge 连续超时备选）”；实体设计登记在设计说明第二行写同一标注，首行按 A2 第 4 点。
7. **安全审核明确拦截。** 仅该轮整图采用既定本地保底，保留完整画面描述，不在 Forge 上换措辞反复尝试。局部编辑仍按第 5 点。

   - **生成。** 使用《工具用法》中的本地 ComfyUI 保底配置。只附一张主体设计或已采纳人物基准，无则选本类风格图。其余要求写进提示词，排除项单列。按工单目标比例生成。透明素材走纯绿底去背。场所 S6 若该路由不能同时承载必附的结构、版本化设计和专用风格参考，记下拦截与路由限制，暂缓该单并处理其他项；禁止把少参考试图当作正式场所成图。
   - **验收。** AI 按共同四查技术。质感略异能否接受、画风是否明显偏离，由用户按本类标准裁定。
   - **登记。** 成图使用共同五第 4 点规定的备用登记途径，在版本 `note` 写“<工单ID> 本地保底版（Forge 安全审核拦截）”。设计说明第二行也写相同标注。首行按 A2 第 4 点。在逐单结果注明保底。后续整张重出可回 Forge。

<a id="art-a4"></a>

## A4　背景、CG 与已开放的道具

1. **适用路线。** 工单画面有可定位场所的背景和 CG，按下列 S0–S7 制作，包括同一场所换时段、天气或状态。无空间场所的抽象背景／CG、对象层已开放的独立道具按 A3 原路线。人物身份、衣装、基准和表情仍走 A2、A5、A6。场所白模只作生产参考，不是成品或游戏场景，也不创设新的游戏对象层。
2. **成品规格。** 按工单宽高与比例定尺寸到新版本，道具框出主体，背景和 CG 框出关键内容。原工单的 fitPolicy 仅作记录。裁掉主体或越界则调取景或重出，禁止拉伸。CG 固定指定瞬间、视角及简报神情；每人参考其身份、服饰和已采纳近景（如有）。含人物的 CG 须满足 A5 定版调度。
3. **用户验收。** 共同四规定技术底线。用户按下列条件退回背景、CG 和独立道具。普通装饰的轻微位置、数量或质感差异，未损害用途可接受；有身份、数量或状态依据的指定实体按其依据核对。
   - **内容。** 漏掉点名主体，时令、空间结构、透视、支撑、尺度或遮挡明显违背原文，画入禁止提前出现或由立绘持有的物件，CG 瞬间或视角明显有误。
   - **一致性。** 同一物件跨图、跨状态或相对绑定设计的类型、结构、颜色、材质明显不符，画风偏离（如塑料感 3D、平涂动画、严重偏色）。CG 人物另按 A5 核身份、衣装、表情。用户退回后按问题补参考、整张重出或局部修订，道具整张重出。

<a id="art-spatial"></a>

### 场所背景与 CG 的空间白模

下表是场所制作的完整顺序。演出确定镜头和画面承载，非人物线按已登记设计搭建可回溯的空间并摆相机。S0–S6 由生产者执行；事实缺失向演出收回明确决定，视觉质量随 S7 交用户。实际文件、工具与参考图排版查《工具用法》。

已有可用白模时，演出 4e 绑定实际版本和机位。首次搭景时，演出先定取景、计划机位 ID、预期入画实体、制作归属和真实前置；第 5 步可据此登记设计及待制作的下游单，按演出册核实设计交接。白模版本、视锥和实际可见实体留待生产生成，计划 ID 不当作实渲证据。S0–S4 完成后，演出执行者据视锥和机位可见清单确认与已定演出相符，非人物主会话将实存白模、机位及资料回填原工单并回读，再进 S5。主体增减、空间事实或构图有实质分歧时退原负责步骤定案。这次核对落实导演决定，不是另请用户早审。

| 工序 | 工作、依据与交付物 |
|---|---|
| **S0 备设计** | 总体及所需组成部分的实体设计已出齐、登记且可取图。总体俯视平面应能读出固定结构、位置、朝向、数量、比例或尺寸。缺图先做授权内设计单。非人物设计登记待用户审即可开工。 |
| **S1 列空间事实** | 每个场所一份设计清单，覆盖该场所全部已登记实体及独立组成部分。逐项列实体 ID、设计版本、图和原文出处、数量、位置、朝向、尺寸、材质分区及适用状态。不同图的门位相互矛盾、尺度或远景依据缺失时，列出具体差异，交演出定案并回写来源。不得从透视图目测补数。 |
| **S2 建白模** | 以清单、俯视平面和已定关系搭建。每个物体绑定实体 ID、设计版本及出处，各材质区可辨。每版有唯一场景数据和俯视图，以场所实体和版本关联，逐项核实体、变换、材质及来源记录。将俯视图与设计平面并排留给 S7。搭建中发现缺事实，回 S1 找演出。设计变更时生成新白模版本，找出并重渲所有依赖机位。历史机位保留原引用。 |
| **S3 落机位** | 依 4e、成图工单的取景放置相机，记录白模版本、机位 ID、位置、朝向、视场角和视点高度，产出俯视视锥图。同机位跨状态复用相机参数。用实际机位的可见实体 ID 双向核对工单绑定，另区分 CG 人物、持物等非固定主体。部分露出或遮挡也要记录。差异交演出定机位、状态或设计修订；不得删除固定实体、改禁画提示来制造“裁出”。 |
| **S4 渲结构参考** | 每个机位按本单天气、光照和状态生成灰模、深度、法线、线稿、实体分色图，版本关联到本单。阴天灰模避免硬日影。分色与实体 ID 有对应表，能查清门扇、门槛等组成部分。 |
| **S5 做本地结构图** | 用本地结构工作流，以灰模为第一参考、绑定场所设计为第二参考生成结构图。目标是保持实体齐全、位置与机位一致。生成灰模与结构图的对照或叠图，供 S7 使用。不得仅用线稿替代结构图，不能把未经裁定的远景搬入白模。 |
| **S6 出最终整图** | Forge 参考 1 固定为结构图，仅定布局。其余参考必须覆盖每一入画实体的已登记设计（含 CG 中每个人物身份）及该类专用风格图；风格图独立占一张。多实体可共用已核实的同一设计页，或等比排成索引板，逐格标 ID、版本及来源，保留足以辨识身份和材质的细节，不拉伸。把实际参考槽与实体逐一对应。总计最多五张；仍无法表达就退演出调构图／拆镜。提示词明确灰模和结构图的颜色、光影、材质、枝形是占位，按实体设计还原。 |
| **S7 整场交用户核图** | 按分色 ID 提取各实体轮廓叠到成图，附实体／版本索引、机位视锥、设计平面与白模俯视对照，以及同机位各时段／状态的并排成图。用户按 A4 逐个核位置、数量、遮挡、材质、未经设计的增物和跨状态结构。可记录偏差像素及占画宽比例；未定通用阈值时由用户结合工单判断，不以试点偏差作合格线。屋外远景、降雪或植物要追到本次设计状态和机位依据，否则列疑点。只有一个状态时注明无跨状态对照。 |

## A5　人物基准与样板

**套装计划。** 按演出已登记的整套状态表检查本次授权项，不自行增删表情。组件编号只用于管理，每状态交完整透明 PNG。

| 核对单位 | 记录 |
|---|---|
| 人物与兼容组 | 年龄阶段、身份设计版本。病容、伤口、污损标发生与恢复锚点。每个姿势和景别单独定身体基准，记录兼容组 ID、基准资源／工单／文件版本与哈希、画布及锚点。换衣或换姿势须另组。 |
| 每个合法状态，一行 | 唯一状态 ID、角色、年龄、基准整图及版本、衣装、表情／视线、兼容组、引用的场景与步骤。无实际引用的常见心境按演出册 4c 处理，仅工单的 `step_ids`、`unit_ids` 留空。按状态核对制作、登记及该版本的用户结论。 |

**开工时查实际前置。** 依赖关系见演出册 [4c 人物套装](苍岐演出与美术统一规则.md#stage-4c)。所用前置成图须可取回采纳版本。身份或衣装改版时，列出基于旧版的基准、差分和相关 CG。用户对照新版决定哪些基准可沿用；需重做者先改绑并采纳新基准，再重做该组受影响差分和 CG，保留旧版关联与决定。

**姿势。** 逐项读【姿势要求】和人物简报。新姿势、指定具体姿态或前次姿势失败，必须用 PosePipeline，由本套生产者取得并实际附入对应姿势参考，将白模与姿势要求一并交用户对照。中性正面自然站立已有合格参考可免，汇报写原因。同一套全身、近景用同一白模。提示词写清朝向、重心、头部、肩背、手位、持物及禁用姿态。

| 基准 | 原图构图与边缘 | 候选定尺寸 |
|---|---|---|
| 全身 | 站立为正面平视、中性表情、自然站立。头、双手、双脚、完整衣装四边留空。坐卧以工单姿势和取景为准。原图碰任一边即作废。 | 站立 1024×2048，脚底 (512,2030)，主体高 1980。坐卧全身按 `technical` 和正文给定画布、锚点、高度。 |
| 近景 | 有全身则参考其采纳图另出，手位和持物一致。站立为头顶至大腿中段，头顶约上方 1/10，底边截身，尽量收臂，最宽不超过画幅一半。仅近景套装以身份、服饰设计和白模为参考，按工单取景。原图头顶、两侧完整，只许触底。 | 1024×2048，主体底边 (512,2044)，高 1840。仅近景姿势取正文的主体高。 |

- **先验原图、再定尺寸。** 真透明原图按《工具用法》的原图边缘检查取人物外框（alpha > 16）。与原图边界对照，碰到上表要求留空的边，原图直接作废，不能用缩图掩盖截断。
- **仅近景定尺寸报左右越界。** 先试本单其他原图，再保持手位收窄重出。坐姿膝／衣摆过宽则让人物在图中缩小、居中。重出两次仍越界，高度改为 `1840 × 1008 ÷ (1024 + 左越界 + 右越界)`，取整，下限 1600，汇报实际值，计数按 A7。
- **基准的用户验收。** 用户原尺寸并排核身份和衣装设计，逐条对照工单与姿势要求、白模。摆拍、性格不符应退回。核肤色、光照、体型、衣装层次材质、手指数、肢体五官、角色画风与同角色既有图。原图和成品均须符合上表裁切边界；技术项由共同四核，视觉细节由用户判断。
- **用户判断是否为「同一个人」。** 看脸型、下颌线、眼形眼距、眉形、鼻、嘴宽、年龄感、肤色、发际线、发型发饰。全身对身份设计，近景对已采纳全身。仅近景对身份设计及已有同人基准，差分对同规格基准，CG 对身份设计及已采纳近景（若有）。变年轻、换脸或平添腮红退回。

<a id="art-early"></a>

**角色定版。** 每个角色的身份设计、衣装设计和首张基准样板为一组，按版本一次交用户确认。身份、衣装登记后，可先用于做同组首张样板。已有服装／姿势样板单优先，否则取角色首张适用基准；已有用户明确选为该角色定版的同一版本可直接引用。仅有单场通过记录时向用户确认该版能否作为定版，保留原场结论。后来对同版的明确退回仍然有效。仅出现在 CG 的角色确认身份与衣装，样板栏写“不适用”，不用建无演出需求的立绘。三项中的适用项尚未齐全或确认时，调度清单标“待用户确认”，暂缓该角色其余基准、全部差分及含该角色的 CG。未确认设计版本仍为“待用户审”，不改工单 `depends_on`。其他角色及非人物单照常。只有等待项且已穷尽可做工作时，保存具体版本、待确认项和恢复条件。

用 A7 的汇总工具生成角色定版包，列适用的实际版本、原图和 A2／A5 对照。用户可将样板放到实际背景与对话框查看。逐项记录版本与“通过／退回”；退回只返工相关项并追踪被替换的前置。适用项全获确认后释放后续工单，后续每组不再增设早审。早期已确认的样板或用户在整场确认的其他组样板，可用来冻结对应兼容组；组内新单随组冻结。其余组按候选规格生产。工单 `technical.status` 的候选／冻结只管规格。冻结画布取组内宽高和双锚点，主体高取“样板实际主体高 × 目标画布高度 ÷ 2048”四舍五入。需改画布或锚点时先退演出修整组，重做受影响图片。

## A6　表情与视线差分

1. **选基准与约束。** 直接输入同兼容组已采纳基准（取到 `base-NN`）。按 `scene_ids`、【表情要求】的指针及其沿用的前场，读 `D:/CangqiStudio/AVGStudio/scenes/<章ID>/03-人物简报.md`。以 `brief.md` 与 `description` 开头的【表情要求】为准。复制工单按共同五第 6 点读取来源首行及其后的【表情要求】。普通差分一次一个状态，只动所需五官及视线，保持画布、姿态、头部、服装、遮挡、光照和位置。按《工具用法》由采纳基准确定头部框，须完整覆盖发顶和下颌。对齐、检查、审图全用同一个框。
2. **AutoExpress 拆分。** 用 ComfyUI + AutoExpress 对已采纳基准的脸部重绘，得到当前状态的表情，不经 Forge。写清需要变化的眉、眼睑、视线、嘴角或嘴形，提示词与采样设置查《工具用法》。保留身份设计中的脸型、五官、瞳色、年龄和肤色。遵守简报禁用表情，避免原设计没有的腮红、泪光、眼影、少女化、歪头或眨眼。普通、大幅和仅微调视线三类按对应幅度生成。本步结果只作下一步的表情参考，脸部可能有撕裂、画风不一致或线条残影，不直接合成、不交付。
3. **Forge 重绘。** 把上一步的 AutoExpress 结果作为表情参考图，连同已采纳基准和身份设计图送 Forge 重绘一次，得到当前状态的整张图。基准是底图，身份、头发、发际线、脸型、服装、手、姿势、画布和透明背景保持不变；表情参考图只提供眼睛状态、视线方向和嘴形，其中的撕裂、画风不一致和线条残影不得带入，眼睛的瞳色、睫毛、眼线和笔触画法同基准。附图顺序、提示词和调用查《工具用法》。本步每次一个状态，实际技术失败按 A7 计数。
4. **贴回基准。** Forge 重绘是整张重画，不整张交付，只把本状态变化的五官区域贴回基准。在基准头部上圈出一块遮罩，须整块盖住原来的眼睛及睫毛、眼线、眼褶；带笑或改嘴时加嘴及口周，明确改眉才纳入眉。遮罩避开头发、刘海、发际线、脸部外轮廓、耳、鼻和颈；两者冲突时以盖全旧眼线、睫毛、眼褶为先，略碰几缕发丝而无断发、色块或直边可接受。重绘图先与基准对齐，再按《工具用法》用 ComfyUI-Inpaint-CropAndStitch 贴回变化区域。允许遮罩边缘向外 40 像素用于贴合，此范围以外的像素保持基准原样，全图透明通道与基准一致。取景不合则作废重出。不用整块贴脸。
5. **技术检查及用户对照图。** 生成本轮贴回检查、局部改动结果、灰底预览、逐眼图和三格脸部图（基准／成品／改动标红）。AI 按共同四执行，技术通过且一瞥无异常即登记。警告、需人工复判或有疑点的项在包内标“建议用户优先看”，保留原始结果；不等待逐张确认。
6. **用户逐项验收。** 用本单真实逐眼图和三格脸部图检查；指定单眼按单眼验。贴回区略软、瞳色略深或眉形略变，而身份和要求的神情清楚时可接受。证据不清先补图。
   - 在 `eyes-review.png` 逐只核瞳孔完整、落点合理、双眼同向同睁（指定单眼按工单），眼线睫毛单层清晰无重影断线，瞳色、眼形、眼距同基准。
   - 在 `face-review.png` 并排核 A5 的「同一个人」及本状态神情是否清楚、幅度合性格。逐项写脸型／下颌／眼／眉／鼻／嘴／发际与刘海／贴回痕迹。有方块、直边、色斑、亮点、杂点、断发、双轮廓、新添眼影、眼皮棕色晕染、腮红或锐度不一致，退回。
   - 看第三格。只许对应眉、眼、眼睑、视线、嘴或口周变红，本状态需修改颧部时也可包含该区。头发、刘海、发际线、脸部外轮廓、下颌、耳、鼻、颈处变红，且成品在该处可见直边、断发、色片的，该项不通过。只有变红而看不到上述缺陷，或仅有零星孤点，此项通过。
   - 用户指出成品具体位置和条款后退回。两版技术均通过、身份和所需表情／视线均成立，仅余局部视觉瑕疵时，用户可以继续退回，也可以明确选较轻版并记录所选版本及接受的瑕疵。任何人不得代用户选择。
7. **整套验收。** AI 按唯一状态 ID 核实授权范围与实际引用齐全，比较同组画布尺寸、锚点，复制／直接复用核来源及本场采纳文件哈希。每组用实际采纳图自动生成总览及切换预览。无差分的组核基准，单状态组标无切换项。用户在整场包逐状态看脸部、神情幅度及切换时的身体、衣装、头部位置。两个景别都有时并排核身份与衣装。复用同图可引来源审核图；无来源图则把本场采纳图与同组采纳基准原尺寸并排。只授权部分状态时列缺项，不签全套。复制错误先取正确版本。来源本身不适用则退演出 4e 改选或登记新需求；返工后再以新版本查受影响整组。

## A7　登记、返工与结束

<a id="art-common-4"></a>

### 共同四　技术底线与用户验收

**AI 的技术检查只含以下项目。** 生成工具的成败、文件缺失、绑定或机位 ID 是否能回读属于生产事实。它们不授权 AI 评判图像好坏。

| 对象 | 必须满足的技术条件 |
|---|---|
| 所有设计图和成品 | 可读 PNG、目标宽高，定尺寸结果无拉伸、误裁、越界。设计图核原图尺寸。工单格式另有记录时交 PNG 并注明。 |
| 人物基准与透明素材 | 人物基准原图和定尺寸结果符合 A5 表中对应的留边／触底范围，主体内部 alpha ≥ 250，无硬切。人物和已开放道具真透明、无明显色边残底；设计图、背景和 CG 不透明。使用绿幕时按 A3 处理。透明像素下的残留颜色不计缺陷。 |
| 差分与局部修补 | 差分取景对齐，贴回检查 `stitch-check.json` 为 `pass`（允许范围见 A6 第 4 点），`locality-qa.json` 无 `fail`。局部修补用实际编辑范围，局部检查须通过。缺检查产物先补齐。对差分，`warnings` 非空、`warn` 或 `needs-visual-review` 随包提示。 |
| 同图复用与整套 | 来源与目标采纳文件 SHA-256 相同；同兼容组状态的画布和锚点一致，套装比对资料见 A6。 |

**生产者一瞥。** 按原输出或垫底预览快速看有无大面积撕裂或拼接块、黑图／空图／严重偏色等整图崩坏、多余或残缺肢体、文字水印签名。命中记具体技术失败并重做。其余直接登记，只记“无异常”；有需用户注意之处随包标注。生产者不放大核脸、不逐项点评姿态、风格、衣料或构图。重复使用同一已核文件只核哈希。

**用户的视觉标准。** A2、A4（含 S7）、A5、A6 和本单清单是用户的验收依据。用户看原图或放大图判断脸、表情、手和接缝；灰底预览核透明边缘和位置。人物须满足工单明确要求（如指定暗沉衣料不得出现金属高光）。文字、水印、签名、误裁、残缺、多余肢体或物件同样可退回；非人物内容按 A4 规定。小瑕疵不妨碍用途时，用户可接受并留版本记录。

<a id="art-common-5"></a>

### 共同五　登记并回填工单

1. **资源版本。** 将通过共同四技术检查和一瞥的成品登记到本工单所绑资源，采纳该版本。已有正确版本先核实，避免重复上传。该版进入“待用户审”清单，采纳记录不能替代用户结论。
2. **工单附件。** 用同一份成品作为工单附件，核对资源采纳版本并回填。
3. **回读结果。** 工单状态须为“已登记”，附件与实际采纳的图须一致。有出入查清原因，修复对应环节后重新回读。
4. **备用登记途径。** 工作台不可用时，走《工具用法》列明的同一资产系统接口，包括设计版本备注与修订资料。核返回的 `sha256` 与本地成品 SHA-256 一致，并取得 `result_matches_registry` 为真及“已登记”状态。
5. **逐单记录。** 登记即记录工单、状态 ID（适用时）、实际图与采纳／设计版本、附件匹配、出图及技术失败次数、一瞥结果、警告、特殊来源和用户状态。工具从本单已留存的事实汇总交接包。
6. **复用复制。** 来源工单须已登记。核对本场目标资源用途及人物分类，缺项按演出册“问题退回”。取来源采纳图为 `final-NN/<来源资源ID>.png`，按第 1–4 点登记同图，核上传文件与来源采纳版本 SHA-256 一致。省略生图和重复定尺寸。用户结论仅按下文相同状态、具体版本及同图证据继承。

**计数和重试。** 出图、技术失败、用户退回分别累计。每次实际生成或局部编辑计出图；对齐失败、定尺寸失败、坏透明／不纯绿幕、工具报错无输出以及共同四技术或一瞥未过，按一次发生的技术故障计一次失败，保留产物和原因。A5 仅近景为求适配允许的两次重出和公式缩小按既有定尺寸调整记录，最终仍越界计技术失败。服务未出图按 A3.6 取回／重试；取回同一次提交不重复计数。正常排队、等授权／定版、退演出、用户退回、明确拦截后换保底、已知无原生透明而改绿幕均不计技术失败。重试应改变问题对应的参考、构图、提示或方法。差分技术失败需再生成或绿幕不纯，可按原流程连续三次以内换种子。反复技术失败的单在交接包列实际次数、最近错误和下一动作；暂缺成品则列缺项，不把它写成已登记、已完成或已取得用户结论。

<a id="art-handoff"></a>

**按场生成交接包。** 用《工具用法》所列汇总工具，从真实版本记录、图像路径、工单技术结果和已有用户决定自动生成。每场一包，失败或缺证据的单照实列出。人工不代写技术通过、哈希或用户结论。
1. **逐单清单。** 收入共同五第 5 点的记录、用户退回次数、需用户优先查看的警告、本次可核对的条款和特殊来源（宿主、本地保底、同图复用）。设计附原文与设计依据。
2. **人物。** 同一角色先排列身份、衣装、全身／近景及含该角色的 CG。每个兼容组按基准、各差分生成总览、逐眼／三格对照和切换预览。唯一状态 ID 归首次实际引用场审核；后场引用同状态、同已审版本及相同文件哈希只列来源与“用户已审”。早期已明确确认的同版，列定版决定。尚无实际引用而获授权的常见心境，归首次制作场，明写“无实际引用”；后续首次使用时引用既有用户对该版本的结论。换图、换版本或来源不明须重新呈交。
3. **场景与道具。** 按本场分组生成缩略总览及原图入口；空间单含 S7 全套对照。附本单清单、各类用户验收判据、待确认角色、技术失败和授权外依赖。
4. **回复。** 用户按工单／状态 ID 及具体版本填“通过”或“退回＋一句理由＋对应条款”；A6 允许选择较轻版时注明选用版本。没答的项保留待审。用户通过后记录“用户已审”，回读当时的版本或哈希。设计版本同步按 A2 第 4 点更新。

**退回和版本迁移。** 一次用户退回对应一个原单、具体版本和反馈。回读已有返工／设计修订单，若已有同一退回对应的在办单则续用；否则按原工单类型建返工单。记录原 ID、旧版本、问题位置、条款、次数和受影响引用。旧图与历次决定保留，已退回版不作新生产前置。授权内改出新版本，过技术检查后采纳、回填、入下一次交接。角色定版退回仍回该角色定版。
- 设计重做时，未完成下游改绑新设计或在等待阶段绑空版本并依赖修订单。已完成的相关成品列入影响清单；用户确认可沿用时保留历史依据，需重做则以新版本和实际依赖重出。人物按 A5 的基准→差分次序，场所按 S2 更新白模并重渲依赖机位，再重做受影响的结构图、成图和 S7 对照。
- 成品重做时沿用目标资源，采纳新版本并核对应工单附件、版本、哈希；跨场同图复用者重新核来源及本场版本，必要时重新复制、采纳并列入受影响场的复核。只处理实际受影响引用，保留未改状态的既有确认。

**完成口径。** 本批可制作项均已登记或正确复用、附件与采纳图匹配、交接包已生成，可报“生产已交接／待用户审”。有尚未登记的技术失败、前置未满足或只授权部分状态时，报实际范围与缺项。整场所有适用项已有用户决定，退回的版本已完成返工并获接受、实际引用已回读，才报“整场美术完成”。实机显示、存读档和运行效果另验。
